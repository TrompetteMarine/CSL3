# Repo-readiness note — planned Rust+Julia simulation repo (KGi-DISS-I004, D8)

Status: the pipeline in this bundle is repo-shaped; creating the public repo is a
separate, later step (user decision). Nothing here blocks it.

## What is already repo-ready (in this bundle)

- `rustsim/` — zero-dependency Rust crate (std only; xoshiro256++/SplitMix64;
  std::thread fan-out). Modes: `validate`, `pt1`, `cuts`, `pt2`, `pt3`, `pt4`, `traj`.
  Each mode writes one frozen CSV to `out/`. Distributional cross-validation against the
  audited Python engine: 5 pre-stated gates, all passed (record in bundle).
- `make_figs_makie.jl` — CairoMakie figure pipeline, one function per figure, reads only
  frozen CSVs/JSONs; CVD-validated palette; deterministic output.
- Frozen inputs: `00_freeze_figruns.yaml` (+ addenda) fix every sweep grid and seed
  before execution; all paper numbers trace to the hash-frozen I001–I003 bundles.

## Proposed layout for the new repo

```
diss-sim/
  engine-rs/        # the Rust crate as-is (rename from rustsim)
  figures-jl/       # make_figs_makie.jl + Project.toml (CairoMakie pin)
  frozen/           # freeze YAMLs, audited-engine reference values, CV report
  out/              # generated CSVs (gitignored; regenerated by CI)
  formal/           # pointer to csl/csl2 branch lean-diss-core (not a copy)
  CITATION.cff, README.md, LICENSE
```

CI gate: `cargo run --release -- validate` must reproduce the 5 cross-validation cells
within the frozen tolerances before any figure job runs.

## C engine — recorded option, NOT built (user: "if needed")

Trigger: population sizes beyond what the Rust engine sustains comfortably
(N ≳ 10^5–10^6 agents, dense per-agent fields). Interface contract if built:
- same CLI surface (`mode`, cell grid, seed base) and identical CSV schemas, so Julia
  figures and freeze files are engine-agnostic;
- same RNG family (xoshiro256++ seeded by SplitMix64 from `seed_base + cell*1000 + rep`)
  so seed bookkeeping transfers;
- OpenMP for the replication loop; no other dependencies;
- acceptance: the same 5 distributional cross-validation gates against the audited
  engine, plus bit-level agreement with the Rust engine on a 3-cell smoke grid is NOT
  required (different float orders); distributional gates only.

Rationale for not building now: all frozen designs (26×26×40, N=200, T=600) run in
minutes in Rust; no current claim needs larger N.
